## ขอบเขตและสิ่งที่ตกลงแล้ว

- แอปสรุปการลงทุน ข้อมูลต้นทางจริงอยู่ใน Dime ใช้คนเดียวหลายอุปกรณ์ผ่าน Firefox
- มือถือหลัก Samsung Galaxy A15 อนาคต S25 FE ถนัดขวา ตัวอักษรใน Dime อ่านสบาย ต้องการภาพลักษณ์เป็นมืออาชีพ เลิกสไตล์ Pixel แบบเด็ก
- งานหลักคือดูยอดรวมและ Heatmap; กราฟการเติบโตเปรียบเทียบกับอดีตของพอร์ตตนเองเท่านั้น ตัดการเทียบ S&P 500 ดัชนี และกองทุนภายนอกออก ผู้ใช้ยืนยันให้มีทั้งผลจริงย้อนหลังและเส้นคาดการณ์อนาคต
- บันทึกอัตโนมัติเมื่อผู้ใช้เข้าเว็บในวันที่ 31 มีนาคม, 30 มิถุนายน, 30 กันยายน, 31 ธันวาคม ตามเขตเวลา Asia/Bangkok ผู้ใช้จะเข้าเว็บเอง ให้เก็บยอดล่าสุดของทุกพอร์ตจากการเข้าครั้งสุดท้ายของวัน ไม่จำกัดเวลา 23:00 และไม่ต้องทำงานขณะปิดแอป ห้ามใช้ยอดวันถัดไปอ้างเป็นยอดวันสิ้นไตรมาส
- บันทึกเงินเติม/ถอนแต่ละครั้งพร้อมวันที่ และแยกออกจากกำไรให้ชัด
- ส่งออก `.md` ให้ LUNA วิเคราะห์ แล้วนำผลไปใส่สรุปรายไตรมาสใน Obsidian
- ราคาฟรี สดที่สุดเท่าที่บริการรองรับ ต้องตรวจข้อจำกัดจริง รวมถึงก่อนเปิด/หลังปิดตลาด
- การแก้ล่าสุดของผู้ใช้ต้องชนะข้อมูลเก่าบนอุปกรณ์อื่น การรีเฟรชราคาไม่ใช่การแก้ยอดถือครองใหม่
- ผู้ใช้จะกรอกข้อมูลใหม่เอง รูป Dime เป็นตัวอย่างเท่านั้น ไม่ใช่คำสั่งนำเข้าหรือข้อมูลตั้งต้น
- รองรับหุ้น US/ไทย คริปโต เงินฝาก และพอร์ตเทรด โดยกรอก holdings ที่ถือปัจจุบันเป็นหลัก
- ผู้ใช้เลือกให้ล้างฐานเดิมเพื่อเริ่มใหม่แล้ว ยังไม่ได้ดำเนินการล้างจริง ต้องจัดการไม่ให้แอปรุ่นเก่าหรือข้อมูลค้างบนอุปกรณ์เติมข้อมูลกลับก่อนนำขึ้นใช้งาน
- ใช้งานออนไลน์เท่านั้น ไม่ต้องพัฒนาการแก้ไขข้อมูลแบบ offline
- ผู้ใช้ให้ลองหน้าตาและขนาดตัวอักษรก่อน แล้วปรับหากใช้งานไม่ดี ไม่ต้องถามเลือกขนาดเป็นตัวเลขก่อนทำแบบทดลอง

### D01 — P1: ข้อมูลเก่าทั้งชุดเขียนทับการแก้ล่าสุดได้

`saveData()` ใช้ `dbRef.set(payload)` ที่ root เดียว ส่งทั้ง portfolios, tradingData, snapshots, dividends และอื่น ๆ ทุกครั้ง เวลา `lastUpdated` มาจากเครื่องที่ส่ง และไม่ได้ใช้ตรวจความใหม่ตอนรับ ส่วน `syncLiveMarketPrices()` เรียกบันทึกแม้ไม่มีราคาที่อัปเดตสำเร็จ

ทดสอบ R01: เครื่อง A บันทึกยอดถูกต้อง 10,000 จากนั้นเครื่อง B ที่ยังมียอด 15,000 รีเฟรชโดยไม่มีราคาใหม่ ยอดในฐานจำลองกลับเป็น 15,000 ทดสอบ R02: payload ที่ระบุปี 2020 ก็ได้รับการยอมรับ ไม่มี guard กันข้อมูลเก่า นี่เป็นกลไกที่อธิบายอาการที่แจ้งได้ แต่ยังไม่ใช่การพิสูจน์เหตุการณ์ย้อนหลังใน Firebase จริง

ผู้ใช้ยืนยันเพิ่มเติมแล้ว: กราฟสลับ THB/USD ได้ และคำนวณแนวโน้มจากประวัติพอร์ต ไม่ใช่อัตราผลตอบแทนที่ผู้ใช้กรอกเอง ต้องแยกเงินเติม/ถอนจากกำไรตาม requirement เดิม การเริ่มพอร์ตใหม่ยังไม่มีประวัติให้ประมาณแนวโน้ม จึงต้องแสดงสถานะข้อมูลไม่เพียงพอแทนการสร้างข้อมูลขึ้นมาเอง รายละเอียดเกณฑ์จำนวนจุดข้อมูล ระยะคาดการณ์ และการต่อแนวโน้มเงินเติมต้องอธิบายในแบบคำนวณก่อนนำไปใช้

ความหมายของการเข้าครั้งสุดท้าย: เว็บไม่ทราบล่วงหน้าว่าผู้ใช้จะกลับมาอีกหรือไม่ จึงบันทึกหลังโหลดข้อมูลล่าสุดสำเร็จในแต่ละครั้งที่เข้าเว็บวันสิ้นไตรมาส และแทนที่ snapshot เดียวของปี/ไตรมาสนั้นด้วยครั้งที่ใหม่กว่า เก็บเวลาบันทึกจริง ไม่พึ่งเหตุการณ์ปิดแท็บที่อาจไม่ทำงานบนมือถือ ต้องกันอุปกรณ์ข้อมูลเก่าเขียนทับและกันงานที่เสร็จข้ามวันนำยอดวันใหม่มาลงย้อนหลัง หากไม่ได้เข้าเว็บหรือบันทึกไม่สำเร็จในวันนั้น ให้แสดงว่าขาดข้อมูล ไม่สร้างยอดย้อนหลังเอง

ยกเลิกการเลือกผู้ให้บริการตั้งเวลาภายนอก ไม่ต้องเพิ่ม Cloudflare หรือเปิด Firebase Blaze เพื่อฟีเจอร์นี้ ผลตรวจโค้ดเดิมคงไว้เป็นหลักฐาน ส่วนพฤติกรรมใหม่สรุปในภาคผนวกด้านล่าง

## สถานะส่งมอบ

### ผลตรวจทางเลือกระบบบันทึกเบื้องหลัง — ยกเลิกจากขอบเขตล่าสุด

เก็บข้อมูลที่เคยตรวจไว้เพื่ออ้างอิงเท่านั้น ผู้ใช้เปลี่ยนเป็นเข้าเว็บเองวันสิ้นไตรมาสแล้ว จึงไม่ต้องเลือกหรือติดตั้งทางเลือกต่อไปนี้:

- **Cloudflare Workers Free + Cron Triggers**: มี scheduled handler ที่ทำงานโดยไม่พึ่งเบราว์เซอร์ ใช้ร่วมกับ Firebase เดิมได้ผ่านการยืนยันสิทธิ์ฝั่งเซิร์ฟเวอร์ เป็นตัวเลือกสำหรับทดลองภายใต้เงื่อนไขฟรี ต้องมีบัญชี Cloudflare เพิ่มและทดสอบภาระงานจริง โควตาฟรี 100,000 requests/วัน, CPU 10 ms ต่อ invocation, 50 subrequests ต่อ invocation และ 5 cron triggers ต่อบัญชี เวลารอ network ไม่นับ CPU ไม่ถือเป็นการรับประกันว่าจะเริ่มตรงวินาทีหรือสำเร็จทุกครั้ง ([limits](https://developers.cloudflare.com/workers/platform/limits/), [pricing](https://developers.cloudflare.com/workers/platform/pricing/), [Cron](https://developers.cloudflare.com/workers/configuration/cron-triggers/))
- **Firebase scheduled functions**: ใช้ระบบ Google/Firebase เดิม ต้องเปิด billing บน Blaze มีโควตาฟรีบางส่วนแต่ไม่รับรองค่าใช้จ่ายศูนย์ Cloud Scheduler มี allowance 3 jobs/บัญชี Google และราคานอก allowance $0.10/job/เดือน ยังมีค่าใช้งาน function/บริการเกี่ยวข้อง ([scheduled functions](https://firebase.google.com/docs/functions/schedule-functions), [billing plans](https://firebase.google.com/docs/projects/billing/firebase-pricing-plans))
- **GitHub Actions schedule**: ไม่เหมาะเป็นตัวเลือกหลักสำหรับยอด ณ เวลา 23:00 เพราะเอกสารระบุว่างานอาจล่าช้าหรือถูกทิ้ง และ public repository ที่ไม่มี activity 60 วันจะปิด schedule อัตโนมัติ ([GitHub schedule](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows))

การบันทึกต้องแยกเวลาที่กำหนด เวลารันจริง และเวลาของข้อมูลราคา หากพลาดกำหนดต้องรายงานการพลาด ห้ามใช้ยอดวันถัดไปสร้างประวัติเท็จ ไม่มีการตั้ง automation ใน Codex แทนระบบของแอป

รอบตรวจครั้งแรกเสร็จที่ commit `ed93106bc3023a9b67ae3246013b754b18d3f284` และเก็บสคริปต์ทำซ้ำกับผลเดิมไว้เป็นหลักฐาน ผล 13/13 ในไฟล์เดิมหมายถึงทำซ้ำบั๊กของเวอร์ชันก่อนแก้ได้ จึงไม่ใช้เป็นผลทดสอบรับรองเวอร์ชันใหม่

## ภาคผนวกการแก้ไข — 10 กันยายน 2026

เริ่มปรับแอปแล้วตามคำตอบทั้งหมด โดยมีพฤติกรรมหลักดังนี้:

- เริ่มฐานข้อมูลใหม่แบบว่าง ไม่มี holdings, ปันผล, เป้าหมาย หรือพอร์ตตัวอย่างจาก source
- ใช้ revision และ generation ของฐาน พร้อม conditional write เพื่อหยุดฟอร์มจากอุปกรณ์ที่เปิดข้อมูลเก่า ไม่ให้เขียนทับข้อมูลใหม่ทั้งชุด
- การรีเฟรชราคานอกวันสิ้นไตรมาสไม่เขียน holdings กลับฐาน และคำขอบันทึกที่ขาดการเชื่อมต่อไม่ถูกค้างเพื่อส่งเองภายหลัง
- วันสิ้นไตรมาสตามเวลาไทย เมื่อเข้าเว็บและดึงราคาจบ จะบันทึกยอดล่าสุดของทุกพอร์ต การบันทึกที่สำเร็จครั้งหลังในวันเดียวกันแทนครั้งก่อน หลังพ้นวันจะไม่ย้อนหลัง
- เงินเติม/ถอนบันทึกเป็นรายรายการ พร้อมวันที่ ค่าเงิน และอัตราแลกเปลี่ยนที่ผู้ใช้ระบุ รองรับทั้งพอร์ต holdings และพอร์ตเทรด
- ตารางเติบโตแยกเงินเข้าออกจากกำไรโดย Modified Dietz โดยประมาณ เปรียบเทียบกับประวัติของผู้ใช้เอง และแสดงแนวโน้มหนึ่งปีเมื่อมีข้อมูลจริงต่อเนื่องอย่างน้อย 4 ไตรมาส
- ตัด benchmark กองทุนและดัชนีที่สร้างจากค่าคงที่ออก รองรับสลับแสดงผล THB/USD
- Export Markdown เก็บทุกปี ทุก snapshot, holdings ณ snapshot, cash flows, ประวัติซื้อขาย ปันผล source และ timestamp ของราคา พร้อมรักษาความละเอียดตัวเลข
- ปรับ dashboard/Heatmap/ฟอร์ม/หน้าต่าง modal และ navigation สำหรับจอ 360px; เปิดการซูม และปิด cache/offline worker เดิม

การตรวจรับเวอร์ชันใหม่ใช้ `npm test` ในโฟลเดอร์แอป ครอบคลุมสูตร การชนกันหลายอุปกรณ์ วันสิ้นไตรมาส เงินเข้าออก ซื้อขาย ปันผล import/export และค่าเงินไทย พร้อมตรวจ UI จากฐานจำลองที่ปิด Firebase และ API จริง

### สถานะฐานข้อมูลเมื่อเริ่ม v4
